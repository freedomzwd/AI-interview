# AI Agent Engineering Knowledge Base

## 1. Agent 的基本组成

工程化 Agent 通常由大语言模型、系统提示词、工具集合、状态、短期或长期记忆、执行循环和停止条件组成。普通 LLM 调用只完成一次输入输出，而 Agent 会根据目标选择工具、观察工具结果、更新状态并决定下一步动作。

Agent 不应被理解为“让模型无限思考”。可靠实现需要明确最大步数、超时、工具白名单、参数校验、幂等策略和失败回退。生产系统还需要保存 trace，以便定位模型为什么选择某个工具。

## 2. Tool Calling

工具描述应清楚说明用途、输入字段、输出格式和禁止场景。工具参数必须在服务端使用 schema 校验，不能因为参数来自模型就跳过鉴权或业务校验。写操作需要幂等键、权限检查和审计日志；高风险操作应增加人工确认。

工具返回值应尽量结构化，避免把大量无关文本重新塞回上下文。发生超时或错误时，返回可供模型理解的错误类型，但不能暴露密钥、数据库连接串或内部堆栈。

## 3. Agent 状态与工作流

复杂业务更适合显式状态机或图工作流。状态中可以保存用户目标、候选人画像、已调用工具、检索结果、待确认动作和最终输出。每个节点只负责一个清晰任务，节点之间通过受约束的状态字段传递数据。

使用 LangGraph 时，应为循环设置递归上限，为并行节点设置并发上限，并为外部调用设置超时与重试。可恢复任务需要持久化 checkpoint，但保存状态时必须避免写入明文密钥和不必要的个人数据。

## 4. Agent 与 RAG 的分工

RAG 负责提供可靠知识上下文，Agent 负责流程决策和工具编排。Agent 可以决定何时检索、使用哪个知识库、是否追加过滤条件以及检索不足时是否追问。检索结果必须被视为不可信数据，不能允许文档中的指令覆盖系统规则。

典型流程是：解析用户目标，构造检索 query，执行混合检索，对候选片段重排，将有限上下文交给模型生成结构化结果，再使用 schema 校验输出。

## 5. Memory

短期记忆保存当前会话需要的信息，长期记忆保存跨会话仍有价值的偏好或事实。写入长期记忆前应判断信息是否稳定、是否获得授权以及是否包含敏感数据。读取记忆时应按用户或租户隔离，防止跨用户泄露。

上下文过长时可采用摘要、滑动窗口和重要信息提取。摘要本身也可能产生偏差，因此关键业务事实应保存为结构化字段，而不是只保存自然语言摘要。

## 6. 可靠性与评测

Agent 评测至少覆盖任务成功率、工具选择准确率、参数正确率、平均步骤数、端到端延迟、成本和失败恢复率。测试集应包含正常请求、模糊请求、无权限请求、工具超时、空检索结果和 Prompt 注入等情况。

线上应记录 trace_id、模型、提示词版本、工具调用、耗时、token 使用量和最终状态。日志必须脱敏。模型升级前需要离线回归，避免工具选择行为发生未预期变化。

## 7. 安全

Agent 的模型输出永远不能直接视为可信指令。所有工具调用都必须经过服务端授权、参数校验、资源范围检查和速率限制。检索文档、网页内容和用户上传文件都可能包含 Prompt 注入，应使用清晰的数据边界，并禁止模型执行内容中的隐藏指令。

密钥只通过环境变量或密钥管理系统注入，不能出现在 Prompt、日志、工具返回值或 Git 仓库中。涉及删除、付款、外发消息等重要动作时，应增加确认或审批机制。

## 8. AI 面试系统中的 Agent

岗位匹配 Agent 可以先读取结构化简历，构建候选人画像，再调用岗位模板匹配工具和面试重点工具。题库 RAG 根据岗位、技能和难度召回候选题，大模型负责有限度地个性化改写。评分阶段使用参考答案与采分点约束模型，最终报告聚合单题得分、优势、短板和学习建议。

这类系统的关键不是一次模型调用，而是数据质量、检索质量、状态管理、失败回退和可观测性的组合。
